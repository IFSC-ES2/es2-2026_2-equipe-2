# M-02 — Tempo médio de revisão de Pull Requests

| Campo | Descrição |
|-------|-----------|
| **Nome** | Tempo médio de revisão de Pull Requests |
| **Classificação** | Processo |
| **Objetivo** | Verificar se a revisão de código está sendo feita em tempo hábil, evitando que Pull Requests fiquem parados e atrasem a integração do trabalho da equipe. Ajuda a decidir se é necessário redistribuir revisores ou reduzir o tamanho dos PRs. |
| **Definição / fórmula** | Média de (data/hora de aprovação ou merge do PR − data/hora de abertura do PR), em horas, calculada sobre os PRs finalizados naquele período. |
| **Fonte dos dados** | Histórico de Pull Requests do repositório no GitHub (datas de abertura, aprovação e merge). |
| **Frequência de atualização** | A cada sprint. |
| **Responsável pelo acompanhamento** | Isac Lehmkuhl dos Santos (DevOps/Infra). |
| **Forma de interpretação** | Tempos muito altos indicam gargalo de revisão (poucos revisores disponíveis ou PRs grandes demais). O ideal é manter esse tempo baixo e estável ao longo do projeto; um aumento sustentado ao longo das sprints é um sinal de alerta. |
