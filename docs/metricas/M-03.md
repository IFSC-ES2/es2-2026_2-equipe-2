# M-03 — Bugs encontrados por ambiente (desenvolvimento vs. homologação)

| Campo | Descrição |
|-------|-----------|
| **Nome** | Bugs encontrados por ambiente (desenvolvimento vs. homologação) |
| **Classificação** | Produto |
| **Objetivo** | Avaliar a eficácia do processo de testes antes da entrega, identificando o quanto os problemas estão sendo pegos ainda em desenvolvimento em vez de chegar a etapas posteriores. Ajuda a decidir se o processo de testes precisa ser reforçado antes do merge. |
| **Definição / fórmula** | Nº de bugs identificados em desenvolvimento / Nº total de bugs identificados (desenvolvimento + homologação/produção), no período avaliado. |
| **Fonte dos dados** | Issues classificadas com label "bug" no repositório, com identificação do ambiente em que foram encontradas. |
| **Frequência de atualização** | A cada sprint. |
| **Responsável pelo acompanhamento** | Victor Eduardo Peixer Munarim (Engenheiro de Qualidade/QA). |
| **Forma de interpretação** | Proporção alta de bugs pegos em desenvolvimento é positiva, indicando que o processo de testes está funcionando antes de chegar em homologação/produção. Uma proporção baixa é um sinal de que a cobertura de testes ou a validação antes do merge precisa melhorar. |
